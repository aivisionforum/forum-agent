# Forum 双机排练与验收记录

此文是操作步骤，不是完成证明。基线为 `acceptance-profile.json`，正式结果必须包含 C1–C10、D01–D07 决策、设备/模型版本和原始测量；不修改基线来让失败变成通过。

## 准备

1. 两台 Apple Silicon Mac 各负责一个会场；记录芯片、内存、macOS、App 构建清单、模型 manifest 和两台机器时间。另备 iPhone、Android、外接显示器及实际会场网络。
2. 在无开发环境的 Mac 安装已签名/公证包，按发行手册准备模型。断网后实际识别、翻译、摘要和声纹均应成功；没有模型时应给出明确不可用状态。
3. 提前冻结授权语料：90 分钟受控回放，以及独立的 90 分钟受控真实讨论。涵盖中英、混说、数字/否定、术语、静音、噪声、插话、短尾句；确定人工质量评分和延迟口径。
4. 两台使用同一个活动 ID。新装机先按 [操作指南“会前”](../OPERATOR_GUIDE.md#会前) 建立并停止联调测试场次、配对并让第二台加入活动，再创建各自的正式场次和重新发邀请。正式场次启用全程录音；不得事后把不相关旧场次改归属来凑测试，也不要将测试资料选入报告。
5. 生成证书，在手机系统中安装/信任显示的 CA；核对指纹。连接同一会场 LAN 后扫码，确认没有证书警告且仅能浏览已审核内容。不能通过跳过 HTTPS 警告算通过。

## 每次 90 分钟排练的时间表

| 时间 | 动作 | 必须记录 |
|---|---|---|
| 00–15 分钟 | 两场同时开始；中英/混说；洞察关闭后开启作对照 | 每句音频终点、稳定原文、最终译文、公开审核时间；失败和缺失不能删样本 |
| 15–30 分钟 | 耳机、扬声器、远端和本地同时发言、真实重复句、蓝牙切换 | 原始/处理后段关联、重复/漏识别、匿名误归属、unknown/overlap；断设备需记录 gap |
| 30–45 分钟 | 两端断网、各自继续；刷新大屏；改/隐藏公开内容后重连 | stale/最后同步时间、cursor、撤回到达时间、旧资料不复活、无跨会场写入 |
| 45–60 分钟 | 暂停/取消模型任务，模拟 worker 失败；开始下一场的排队/抢占验证 | 录音是否持续、实际进程退出、恢复来源 revision、排队耗时 |
| 60–75 分钟 | 手机检索、访问过期及 revoke；错误凭证尝试控制/读取音频 | 查询只含已发布正文和证据；控制/私有接口不可访问 |
| 75–90 分钟 | 长发言/最后短句；停止；生成纪要，选择两场公开版本生成报告/闭幕稿 | 最后一句、全场覆盖、停止至完整草稿耗时、审核与引用；失败或部分稿不能算完整 |
| 停止后 | 朗读审核发布的闭幕稿，中途停止/撤回；开始下一场；退出和重启 | 不朗读旧稿、不把朗读送入 ASR、所有设备释放、已有记录可读 |

质量评测需保留两个会场各自的对齐参考。原文/译文、声音、匿名向量均存本地受限目录；仓库只放授权合成 fixture 或不含原文的指标。

| C10 闭幕综述 | 选择/审核/发布/撤回/朗读停止记录 | 待测；设备未释放拒绝开新采集 |

任一未解决的跨场串写、稳定原文丢失、公开草稿泄漏、无法停麦或误停其他应用问题，均阻止最终发布。两次排练和全部证据完成后才标记稳定 Forum 版本。
