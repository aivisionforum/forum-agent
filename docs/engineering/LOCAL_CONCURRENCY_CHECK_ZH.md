# 本机三模型并行实测（2026-09-24）

结论：这台 48 GiB Mac 可以同时运行识别、翻译和会议 Agent。本轮不需要为了并发而更换模型。旧版长时间暂停 Agent 的直接原因包含过于保守的调度；并发时仍会竞争 GPU/内存带宽，不能把内存足够理解为速度没有损失。

## 测试方法

停止并正常保存旧会议后，在三个独立进程中运行现用模型：Whisper large-v3-turbo、Qwen3.5-2B-MLX-4bit、Qwen3-8B-4bit。各进程先加载权重，通过同一个启动屏障开始推理，确认推理时间实际重叠。没有下载或替换模型。

使用本机合成的 6.42 秒英文音频（8 次识别）、12 次中英翻译（含相邻断句及前文），以及 3 次洞察（英文业务主题、中文教育与公共服务主题、纯寒暄）。翻译调用生产 Rust/MLX 后端及最终提示词；识别和 Agent 使用生产 Python 模型类。单独运行和并行运行使用相同样本。

以下为推理耗时，不包含权重校验、模型加载、音频等待、调度和界面刷新。

|任务|单独运行中位数|并发运行中位数|并发最大值|
|---|---:|---:|---:|
|翻译（12 次）|0.61 秒|2.20 秒|3.87 秒|
|语音识别（8 次）|0.94 秒|1.89 秒|3.43 秒|
|Agent（3 次）|8.62 秒|9.66 秒|21.78 秒|

Agent 在三者持续计算的第一轮耗时 21.78 秒；后续轮次在其他进程逐渐完成后更快。Agent 加载和权重校验约 6.38 秒，每个生产任务仍需加载，故 12 秒触发间隔不等于 12 秒必定出现新洞察。

## 内存与质量观察

- 采样得到三个测试进程合计 RSS 峰值约 6.73 GiB。RSS 是进程驻留指标，不等于统一内存总占用，也不覆盖系统和其他应用。
- 系统已有交换内存约 9746 MiB；测试前后相同，没有观察到新增交换。不能把已有交换内存归因于这三个模型。
- Agent 两组实质内容均返回合法、引用有效且无部分失败的结果，主题包括「自建与采购」「知识产权管理」「课堂互动评估」「公共服务监管」。末尾寒暄不挤掉前面的主题，纯寒暄没有主题。
- 翻译可以合并处理自建/采购/第三方的连续短句，并保留采购未决定等否定含义。2B 模型仍偶尔用前文中的具体对象替换当前表达，译法也未必自然；这不是正式会议质量验收。ASR 已识错的专有名词也不能依赖翻译自动纠正。
