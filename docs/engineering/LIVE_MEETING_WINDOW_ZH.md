# 实时会议窗口（2026-09-18）

桌面操作员窗口现在同时呈现双语字幕、匿名标签、洞察草稿与运行状态。手机与局域网公开投影不在本次调整范围。

## 布局与操作

- 默认窗口 1180 × 720，最小 560 × 560。宽窗口左侧字幕、右侧洞察；宽度小于 850 时上下排列，各自滚动。
- 保留上下对照、逐句双行、仅译文及不翻译的已有设置。字幕区显示与原文片段和版本匹配的匿名标签。
- 标题栏左上角是浅灰色关闭、最小化、全屏按钮。拖动标题区域移动窗口，右上角可切换置顶，默认不置顶。
- 关闭会议窗口只隐藏窗口，会议仍继续。主操作台“实时会议窗口 → 打开会议窗口”可重新打开。
- 向上滚动字幕时暂停跟随；点击“回到最新”恢复。洞察与标签状态刷新不会把阅读位置拉回。
- 右侧使用当前场次的分析任务与成果，展示引用数量、审核状态、等待原因、错误及后台提示。支持立即生成和跳转会议工作台审核。
- 匿名标签在主页第 3 项“会议助理”中启用，偏好持久保存，下场开始时自动启用；右侧保留运行状态与主页入口。仍依赖本场已保存录音和本地 ECAPA 模型。未启用、缺少模型、等待计算资源等状态会显示，不自动采音或下载模型。
- 该窗口显示操作员私有内容；手机/只读公开投影继续走已有审核发布路径。

## 数据边界与验证

字幕沿用原有实时投影，额外携带 segment ID 和原文 revision；标签按场次、片段和版本严格匹配。切换场次会销毁旧洞察组件及轮询，旧响应不能覆盖新场次。无当前场次时不从会议库任意挑选历史会议。

浏览器模式使用显式合成预览，禁用任务、声纹与原生窗口操作；桌面空闲窗口不伪造洞察。隐藏、撤回、失效、驳回的洞察不再作为当前卡片呈现。

本轮验证：Svelte 检查零错误/警告；前端 28 项通过；bridge 58 项通过；桌面 Rust 64 项通过、2 项原有忽略；补充了真实 core→字幕投影中的片段/版本保留断言。检查宽屏及最小尺寸的合成预览，开发包执行打包检查和本机签名验证。原生界面已验证关闭/重新打开、最小化/恢复、全屏/退出、标题栏拖动，以及主操作台关闭后的审核入口恢复；验证时没有启动采音。

这些检查不替代真实多人会议的声纹准确率、洞察质量或实时并发延迟验收。之前后台的 `analysis_empty_input` 自动纪要提示属于分析调度问题，本次仅将其状态展示到实时窗口，没有将它当作已修复的模型链路。


## 字幕清理、主题气泡与首页设置

- 字幕只显示识别/翻译文本，删除投影层的 `[en]` 等前缀，以及未识别、识别失败、空音频的内部占位句；失败状态仍保留在会议记录，原文数据不改写。
- 自动双语模式携带每种目标语言的独立文本，始终上方英文、下方中文（逐句模式同样中英对应），避免发言语言改变后两个区域混排；等待另一语言时不显示内部提示。
- 洞察显示最多 5 个主题词气泡，按已引用内容中的出现频次排序；点击气泡筛选对应内容。问题与待确认事项使用对话卡片，其他重点使用普通卡片。气泡轻缓浮动，支持减少动画的系统设置。主题词是已生成内容的导航，不代表额外推断的共识。
- 正常桌面宽度中，洞察内容独立滚动，生成、审核、标签状态固定在底部；窄窗口保持整个洞察区可滚动。
- 首页按 01 语言与音频、02 实时会议窗口、03 会议助理排列。TTS 译文播报、音色和输出设备设置均已移除。会议语言提供中英混合、纯中文、纯英文三种模式；一次选择“中英混合”即可处理中英交替，后两者只转写。

## 2026-09-18：手动生成仍无输出的完整链路修复

本轮故障会议有 132 段采音、124 段有效原文。实际记录同时出现了识别积压中断、`snapshot_stale` 和模型输出被整体拒绝；界面上的 `analysis_empty_input` 则来自更早的空会议。

- 实时洞察快照只固定已经提交的 ASR 版本，未完成尾段不再让已生成的洞察失效；仍标记覆盖不完整，原文的真正修订继续使旧成果失效。
- 短暂识别、翻译与持久化积压立即阻止新后台任务启动；连续 6 秒后，分析进程在模型检查点暂停生成并保留模型与已生成文本，积压清除后继续同一次尝试。准备采音、退出和存储故障仍立即终止后台计算并让出资源。
- 确认分析进程已退出后，资源中断的任务自动重排，等待 10 秒后继续，保留最多 3 次尝试及原有快照、检查点、取消和时限校验。手动请求优先于自动任务。
- 会议期间每 3 分钟只创建实时洞察，完整纪要在停止后生成。没有任何采音的停止请求按标记确认，不删除会议；一个场次暂时不能生成不再阻塞其他场次。后台提示按会议隔离。
- 模型输出逐条严格核验。某条引文不准确时，只剔除该条，保留其他有效条目并标记部分完成；该组覆盖记为失败、不缓存为完整检查点。未放宽逐字引文或来源范围要求。
- 洞察提示限制为最多 3 条、每条最多 2 处短引用；失败重试采用更短的输出提示，并校验上下文预算，避免固定温度重复同一份无效输出。
- 实时面板显示提交、排队、加载、生成、失败及部分完成状态。手动创建成功立即更新任务状态，失败后可以用最新原文重新生成。

连续收音实测表明，单靠延迟中断和 3 次重试仍会在稳定积压下反复丢掉同一组生成进度，因此增加协作式暂停：主机只发送带任务 ID / attempt 的暂停状态；计算子进程在 token 边界停止，回执确认后界面才显示“已保留生成进度”。控制管道仍能取消、响应健康检查；暂停计入原有总时限，不延长预算。旧 worker 缺少该能力时明确拒绝握手，打包检查也验证此能力。

验证：Rust 150 项通过、2 项原有忽略；Python worker 66 项通过；前端 30 项通过，Svelte 零错误/警告。对真实原文的私有 SQLite 副本运行生产调度器和本地 8B 模型，主动制造一次持续积压中断及多次短积压，结果为 `Queued/1 → Running/1 → Waiting/2 → Running/2 → SucceededPartial/2`，约 45.3 秒，得到 2 条带引用的内容，另 1 条错误引用被剔除。探针为 `desktop/forum-shell/examples/live_insight_probe.rs`，只接受临时目录中的数据库副本，不打开音频设备。

这次探针验证实际模型产出、资源中断后的自动继续和部分内容保留，不是麦克风并发压力、长会稳定性或概要语义质量验收；所有成果仍需人工审核。

补充验证：协作式暂停加入后，worker 69 项测试通过，涵盖同一 attempt 暂停/恢复、错误 attempt 拒绝、暂停中取消和暂停不延长总时限；Rust 与前端检查继续通过。真实 8B 探针在一次硬中断后的第 2 次尝试中，连续两次收到计算进程的 `paused → analyzing` 回执，最终 `succeeded_partial`，约 47.8 秒，新任务产出 2 条带引用内容，没有因软压力增加尝试次数。

最终安装包已通过包含暂停能力的 worker 检查与本机签名验证，应用已重启。原生界面已实际显示最新测试场次的“演员、自信、认可、角色、建立”主题气泡与 3 条洞察，并保留用户已有审核状态；重启后停留在该场次的“洞察与审核”结果页。该场次的可见结果是在停止收音后生成的；最终保留进度机制的模型验证使用了真实原文和真实模型、模拟资源压力，尚不能据此宣称长时间真实音频并发验收通过。
