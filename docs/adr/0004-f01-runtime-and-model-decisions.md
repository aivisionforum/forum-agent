# ADR 0004：F01 运行时、模型与跨设备验证决策

日期：2026-09-16。状态：本机工程决策已记录；F01 整体出口等待跨设备实测和用户确认。

本次只完成第一部分 F00–F01。下一部分必须由用户确认后开始；已有 F02-a 不继续扩展。

## 语音与翻译

- 保留导入的 Qwen3-ASR-1.7B 显式语种模式和 Qwen3.5-2B-4bit 翻译，便于验证同一实现的迁移。
- 不把空字符串、字面 `auto` 或固定 English hint 宣称为忠实的自动转写。实测会把中文片段转成英文，原文与译文因此不能混用。
- F03 的自动语种模式以 `mlx-whisper==0.4.3` / large-v3-turbo 的本地 PCM adapter 为实现候选。实测可返回语种，但仍有术语误识别与静音幻觉，必须结合 VAD/无语音门控及失败状态。
- 临时 Qwen binding 实验得到语言标签，但仍改写混说。该补丁只存在于实验目录，不替换生产锁定依赖。
- Whisper adapter 需要额外 Python/原生依赖和包体审计；当前 `.app` 未因此宣称已有自动模式。详见[模型实验](../engineering/F01_MODEL_FINDINGS_ZH.md)。

## 后台模型和并发

8B 保留为洞察/初稿候选；32B 不进入本次常驻组合。48 GiB M4 Pro 上，三个进程可以同时运行，但合成样例中 ASR 中位耗时从 639 增至 986 ms、2B 从 299 增至 509 ms、8B 从 7,530 增至 11,625 ms。摘要进程内第二任务排队从 7,693 增至 13,822 ms。

因此默认工程策略为实时 ASR/翻译优先，后台分析按可中断的小块调度；未取得 F06 端到端证据前，不允许把“能同时加载”解释成可以无条件并发。当前没有接入生产调度器或任务队列。

独立进程 SIGTERM→退出分别约 37.91/18.90/74.76 ms，重启后均能完成推理。这证明硬中断和重新加载可行，不证明生产合作取消、重试幂等或内存完全无残留。RSS 与 MLX 数值不可简单相加当成总统一内存；本次不外推到低内存设备。

8B 虽生成合法 JSON，仍虚构了预算确认行动项。后续洞察和纪要必须关联证据、校验覆盖范围并经人工审核；语法成功不能替代事实正确。

## Dora 隔离和进程所有权

固定原生 arm64 `dora-cli 0.4.1`，每次运行直接启动独占 coordinator/daemon，使用私有 loopback 端口、禁用 Zenoh 自动发现。动态节点显式查询该 daemon，校验 flow UUID、node ID 和事件端口的 PID 归属。

官方 0.4.1 对纯动态图的 stop 完成确认可能不返回，且 daemon 启动的普通 executable 节点会各自创建进程组。只杀 daemon 进程组不构成完整回收。

所以私有运行描述将本地 executable 节点注册为 dynamic，桌面应用直接启动并持有 ASR/翻译子进程；其 `DORA_NODE_CONFIG` 来自已验证的自有 daemon。原模型二进制仍走官方 `init_from_env`。不兼容的 args、重启/构建/远端部署语义明确拒绝。

停止先通知节点，再限时回收每个直接持有的 Child/进程组和 bridge worker。`acknowledged` 与 `contained` 分开记录；CLI 未确认而完成自有资源回收标为 `StoppedByOwnedRuntimeFallback`，不伪造正常 ACK。回收失败时保留所有权，UI 不提前显示已停止，不允许覆盖活跃 worker。

模型、daemon 或 bridge 异常的本机故障测试与实际采音/长期运行是不同门槛。强杀整个桌面宿主后的恢复仍需后续发行阶段验证，不把当前进程内 Drop 路径当成操作系统保证。

真实模型二进制串联验证还显示，控制器成功返回可能早于模型和订阅 ready：早发的单帧未到 ASR，等待日志 ready 后才成功到达。日志门控仅是本次探针方法；F03 必须建立生产就绪屏障与 durable producer ACK/重放机制。F01 不据此宣称启动首帧或可靠尾句已解决。

## Python 分发

采用 hash 固定的 Astral standalone CPython 3.12.11（20250612）、macOS arm64/14+ wheels、MLX 0.32.2、mlx-lm 0.31.3，随 `.app` 资源分发。构建用解释器不进入包，不复制开发 `.venv`/Conda。

默认 worker 只提供版本握手、健康和退出，正式 jobs capability 为空。真实模型诊断必须显式启用且只接受已有本地 Qwen3 快照。stdout 仅承载 NDJSON，库诊断重定向 stderr。

包内 checker 使用标准库解析 Mach-O，无需 otool/Xcode，默认做真实 Metal 小矩阵计算。发行清单包含依赖 URL、SHA-256、版本和许可证；模型权重不打进测试包。ad-hoc 本地签名不等于正式签名/公证。

## 局域网信任部署

F01 使用可销毁的 HTTPS 合成页面验证证书信任和限时配对，不开放旧控制台或会议数据。只监听显式私有 IPv4；测试 CA 两天有效、签发后删除 CA 私钥；配对令牌放 URL fragment，成功后换 Secure/HttpOnly cookie。请求有绝对期限，整个服务 20 分钟到期，退出删除服务器私钥。

手机和 Mac 仍需实测安装证书、可信 HTTPS、并行访问、过期/断开与无令牌拒绝。房间间完整同步协议、权限角色、二维码体验及正式信任部署属于 F10，不能由本探针代替。当前 F01 跨设备结果仍是 pending，按[设备验收表](../engineering/F01_DEVICE_TEST_ZH.md)收集后更新。
